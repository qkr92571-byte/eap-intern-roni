# 첨부파일 Firebase Storage 업로드 비용 분석

## 개요
추출한 첨부파일을 Firebase Storage에 업로드하고 프론트엔드에서 다운로드할 수 있게 하는 기능 추가 시 예상 비용 구조 분석

## 현재 상황

### 저장 방식
- **로컬 파일 시스템**: `backend/downloads/YYYYMMDD/{공고번호}/` 디렉토리에 저장
- **Firestore**: 메타데이터만 저장 (파일 경로, 파일명 등)
- **비용**: 서버 스토리지 비용만 발생 (호스팅 비용에 포함)

### 현재 파일 현황
- 총 파일 수: 약 10-20개 (공고당 3-5개 파일)
- 총 저장 용량: 약 1MB 미만 (현재 888KB)
- 파일 형식: HWP, PDF, DOCX, MD, ZIP

## 제안된 구조

### 저장 방식 변경
```
로컬 파일 시스템 → Firebase Storage
```

### 구현 방식
1. 첨부파일 다운로드 후 Firebase Storage에 업로드
2. Firestore에 파일 메타데이터 저장 (Storage URL 포함)
3. 프론트엔드에서 Storage URL을 통해 다운로드

## 비용 최적화 전략

### 1. 파일 압축
- ZIP 파일로 압축하여 저장 용량 감소
- 예상 절감: 30-50%

### 2. CDN 활용
- Firebase Storage는 자동으로 CDN을 통해 제공
- 캐싱으로 다운로드 비용 절감 가능

### 3. 다운로드 제한
- 사용자당 다운로드 횟수 제한
- 프리미엄 사용자만 다운로드 허용

### 4. 파일 보관 정책
- 오래된 파일 자동 삭제 (예: 1년 이상)
- 자주 다운로드되지 않는 파일은 아카이브

### 5. 지역 선택
- 사용자 대부분이 한국에 있다면 아시아 태평양 지역 선택
- 네트워크 지연 감소 및 비용 최적화

## 대안 솔루션 비교

### 옵션 1: Firebase Storage (제안)
- **장점**: 
  - Firebase 생태계와 통합 용이
  - 자동 CDN 제공
  - 보안 규칙으로 접근 제어 가능
- **단점**: 
  - 다운로드 비용이 높음 ($0.12/GB)
  - 월 예상 비용: $0.36 - $12/월

### 옵션 2: AWS S3 + CloudFront
- **장점**: 
  - 다운로드 비용이 더 저렴할 수 있음
  - 더 세밀한 비용 제어 가능
- **단점**: 
  - Firebase와 별도 관리 필요
  - 설정 복잡도 증가
  - 월 예상 비용: $0.20 - $8/월

### 옵션 3: Google Cloud Storage
- **장점**: 
  - Firebase와 같은 Google 생태계
  - 다운로드 비용이 상대적으로 저렴
- **단점**: 
  - Firebase Storage와 유사한 비용 구조
  - 월 예상 비용: $0.30 - $10/월

### 옵션 4: 하이브리드 방식 (권장)
- **현재 방식 유지 + 선택적 Storage 업로드**
- 자주 다운로드되는 파일만 Firebase Storage에 업로드
- 나머지는 로컬 파일 시스템에 유지
- 백엔드 API를 통해 직접 다운로드 제공
- **장점**: 
  - 비용 최소화
  - 필요한 파일만 Storage 사용
- **단점**: 
  - 구현 복잡도 증가
  - 두 가지 저장 방식 관리 필요
