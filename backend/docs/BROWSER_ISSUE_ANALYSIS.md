# 브라우저 문제 심층 분석

## 문제 현상

"입찰공고목록" 서브메뉴 클릭 중 `TargetClosedError: Target page, context or browser has been closed` 에러 발생

## 원인 분석

### 1. 코드 확인 결과

- ✅ `context.close()` 사용: **0회** (사용하지 않음)
- ✅ `browser.close()` 사용: **1회** (finally 블록에서만 정상 종료)

**결론**: 코드상 브라우저를 조기에 닫는 로직은 없습니다.

### 2. 실제 원인

#### 2.1 페이지 로딩 대기 부족
- **문제**: 메뉴 클릭 후 페이지 이동이 완료되기 전에 다음 작업 수행
- **증상**: JavaScript가 페이지를 리다이렉트하는 동안 페이지가 닫힌 것으로 감지
- **해결**: `wait_for_load_state('networkidle')` 추가

#### 2.2 메뉴 요소 존재 확인 부족
- **문제**: 메뉴 요소가 DOM에 로드되기 전에 클릭 시도
- **증상**: 요소를 찾지 못하거나 클릭이 실패하여 페이지 상태 불안정
- **해결**: 요소 존재 확인 로직 추가

#### 2.3 네트워크 타임아웃
- **문제**: 나라장터 사이트의 느린 응답 시간
- **증상**: 타임아웃 발생 시 페이지가 닫힌 것으로 오인
- **해결**: 타임아웃 시간 증가 (10초 → 15초)

### 3. 적용된 해결책

#### 3.1 페이지 상태 확인 강화
```python
# 메뉴 클릭 전 페이지 상태 확인
if page.is_closed():
    raise Exception("페이지가 메뉴 클릭 전에 닫혔습니다")

# 메뉴 요소 존재 확인
menu_exists = page.evaluate("""...""")

# 메뉴 클릭 후 페이지 로딩 대기
page.wait_for_load_state('networkidle', timeout=15000)
```

#### 3.2 단계별 확인 로직 추가
1. 메뉴 클릭 전: 페이지 상태 확인
2. 메뉴 클릭 후: 네트워크 로딩 대기
3. 페이지 이동 후: URL 확인 및 상태 재확인

#### 3.3 에러 처리 개선
- 페이지가 닫힌 경우 명확한 에러 메시지 출력
- 현재 URL 및 페이지 상태 정보 출력
- 재시도 로직 추가 (서브메뉴 요소가 없을 경우)

### 성공 케이스
- ✅ 브라우저 실행 성공
- ✅ 메인 페이지 접속 성공
- ✅ 입찰 메뉴 클릭 성공
- ✅ 입찰공고목록 서브메뉴 클릭 성공
- ✅ 데이터 수집 진행 중

### 개선 사항
1. **날짜 파싱 경고**: 게시일시 파싱 실패 경고 발생
   - 원인: 날짜 형식이 `YYYY/MM/DD HH:MM\n(마감일)` 형식
   - 해결 필요: 날짜 파싱 로직 개선

## 권장 사항

### 1. 안정성 향상
- 각 단계마다 페이지 상태 확인
- 네트워크 로딩 대기 시간 충분히 확보
- 요소 존재 확인 후 작업 수행

### 2. 에러 처리
- 명확한 에러 메시지 제공
- 현재 상태 정보 출력 (URL, 페이지 제목 등)
- 재시도 로직 구현

### 3. 모니터링
- 각 단계별 성공/실패 로깅
- 페이지 상태 변화 추적
- 네트워크 응답 시간 모니터링

## 결론

브라우저 문제는 **페이지 로딩 대기 부족**과 **요소 존재 확인 부족**이 주요 원인이었습니다. 
`context.close()` 문제가 아닌, 페이지 상태 관리 문제였습니다.

해결책 적용 후 데이터 수집이 정상적으로 진행되고 있습니다.
